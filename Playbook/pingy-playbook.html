01

What this session already fixed

Two audits ran against the real code (engine, C layer, buffers, UI). Their confirmed findings that affect correctness got fixed in this batch, because "loss is not calculated properly" turned out to be several real bugs, not one formula.

ProblemWhat went wrongStatus
Stale replies faked 0 ms pingsEvery probe used sequence number 1, and the parser accepted any echo reply. A late reply from a timed-out probe sat in the socket buffer and got timed against the next probe's send. One slow patch poisoned min, avg, and jitter forever, and the stream could stay offset by one probe permanently.FIXED per-probe sequence numbers, seq matching in both parsers, and a drain of stale packets before each send. Android, iOS, and desktop all share the fix.
Socket errors spun the CPUA firewall that rejects ICMP made the loop do open, send, fail, close, repeat with zero delay at interval 0. Thousands of fake "lost" samples per second, hot battery.FIXED 200 ms backoff on the socket-error path.
One DNS hiccup killed the panel foreverA failed resolution was cached as if it were the answer. The panel then showed 100% loss until removed.FIXED failures are never cached, retried every second. A socket error also clears the cache so a network change re-resolves.
Lifetime stats liedLoss and averages accumulated since panel birth. A bad minute an hour ago still haunted the numbers.FIXED all stats are now windowed to the same timeframe the graph shows. The trouble scrolls away, the numbers recover.
Removing a panel took up to 3 sCancellation cannot interrupt a blocking poll(2). The socket stayed open until the timeout expired.FIXED stop() closes the fd directly, which wakes the poll immediately.
Interval was dead codeThe engine supported intervals, but no slider existed since the redesigns. Zero-interval was the only reachable mode.FIXED interval slider is back (adaptive to 2000 ms).
One-outstanding-probe blindnessThe old loop sent a probe and froze until it resolved. Each timeout meant 3 s of not sampling at all, so count-based loss under-weighted outages by up to 100x, and time-based loss would have counted blind waiting as downtime.FIXED the engine is pipelined now: a send schedule fires seq-stamped probes and never waits (adaptive mode: each reply pulls the next send once the pipeline drains; a 250 ms watchdog keeps sampling through outages), replies are matched to probes by seq, and expired probes are reaped without stalling anything. Verified live: healthy cadence = 1/RTT, outage cadence = exactly 4 verdicts/sec.
Loss had no time dimensionCount-based LOSS alone could read 1% during a half-window blackout.FIXED new GONE stat: the share of the window's resolved time covered by spans ending in a lost verdict. With pipelined probing it is honest in both directions (a blackout reads ~100%, one dropped packet reads milliseconds). Shown next to LOSS; the pair diagnoses: high GONE + low LOSS = long outage, the reverse = rapid sparse drops.

Also in the batch: draw pass now walks the ring newest-first and stops at the window edge (no more full 6000-slot scan per frame), per-pixel folding caps draw cost at any probe rate, and the panel no longer recomposes on every ping.

02

Hostile-network survival map

One mechanism exists today on all three platforms: unprivileged ICMP echo over SOCK_DGRAM + IPPROTO_ICMP, one connected socket per panel, pipelined (many seq-matched probes in flight; timeouts never pause the schedule). No exec of ping, no fallback. This is the honest map of what happens under each condition.

03

The probe tier ladder

The design rule that keeps the data honest: never fall back per probe. Mixing ICMP and TCP samples in one graph makes the average meaningless. Instead, run a capability handshake when a panel starts, pin the best working tier for the session, tag every sample with its tier, and rerun the handshake on a network-change event.

Tier 0 · ICMP echo (exists today)

Kernel-answered, no server-side app delay, best fidelity. Now trustworthy (seq matching) and pipelined (no blind waiting). Stays the default wherever it works.

Tier 1 · DNS query over UDP/53

A real A-record query to the target, timed to the response. Only meaningful for resolvers, and three of the eight presets are resolvers (1.1.1.1, 8.8.8.8, 9.9.9.9). UDP/53 survives most firewalls that drop ICMP. Android: DatagramSocket with soTimeout. iOS: NWConnection with .udp.

Tier 2 · TCP connect (the universal fallback)

Measures SYN to SYN-ACK: the moment connect() returns. Details in section 06. Works against almost anything with an open port, and brings IPv6 and interface pinning along.

Tier 3 · HTTP HEAD (reachability + portal detection only)

Not comparable to the tiers above (TLS and request cost). Never enters the RTT average. Its job is the binary question "is the internet real here" and catching captive portals.

The panel header shows the active tier as a small tag next to the address whenever it is not ICMP, so a TCP number is never mistaken for an ICMP number. The failure reason enum (resolve failed, no route, rejected, timeout) is the prerequisite work: the handshake needs to know why a tier failed to decide whether to demote.

04

Concurrency: what changed, what stays open

The audit went deep on the Kotlin-to-C boundary and the coroutine layout. Verdict before fixes: not sound at zero interval. Verdict after: the correctness items are closed, two efficiency items remain by choice.

Closed today

  • Ring buffer reader vs writer. Readers now walk newest-first, away from the writer's clobber point, and stop if ages go non-monotonic. last() derives everything from a single volatile read of the write cursor, killing the torn-read that could return null right after a ping landed.
  • Engine reference visibility. The engine field is volatile; slider changes from the Default pool can no longer read a stale null and silently drop an update.
  • The fake outer timeout. withTimeoutOrNull around a blocking native call cannot fire (cancellation lands only at suspension points). Removed. On iOS it also taxed the single Kotlin/Native timer thread per probe. The native poll budget is the one authority, and stop() closing the fd covers the wedge case for real.
  • IO pool starvation. Each engine now runs on its own single-lane limitedParallelism(1) view, so many panels can no longer eat the shared 64-slot IO pool from under the rest of the app (DataStore writes included).
  • Panel identity in lists. Panels are keyed by IP everywhere, so removing one no longer hands its peak-hold line and aura state to the neighbor.

Open, on purpose

  • Blocking resolve. OPEN getaddrinfo on a captive portal can block a lane for many seconds. Contained (one lane per engine, failures retried), but the clean fix is resolving before engine start inside the panel scope, where close() cancels it.
  • Write-side downsampling. OPEN the draw pass now folds to one entry per pixel, so rendering is cheap at any rate. The ring itself still stores every raw sample (6000). If a "30 s window at LAN speed" ever matters, bucket at write time (keep min, max, last per display slice).

05

Force cellular ("force 4G")

The question this feature answers: "is my mobile data actually good right now, while I am on Wi-Fi?" Both platforms can pin the existing ICMP socket to the cellular interface. No root, no tricks.

Android

ConnectivityManager.requestNetwork with TRANSPORT_CELLULAR keeps mobile data alive next to Wi-Fi, then network.bindSocket(fd) pins our ICMP fd to it. Needs the normal CHANGE_NETWORK_STATE permission. The request must stay held while the panel lives, and released on close, or the radio idles back.

iOS

BSD sockets pin with setsockopt(IP_BOUND_IF) using the cellular interface index (the pdp_ip family). One new parameter through the cinterop. NWConnection's requiredInterfaceType is the cleaner API but only matters if the TCP tier wants it too.

UI shape

A per-panel interface selector: Auto, Wi-Fi, Cellular. Sits in the settings deck as one more compact row. The panel readout gets a tiny antenna tag when it is not Auto, same language as the tier tag.

Honest caveats

Bringing the cellular radio up costs battery and a second or two of admission delay, so the first samples after switching are marked warm-up and excluded from stats. Dual SIM picks the active data SIM; per-SIM selection is not worth the API pain today.

06

TCP ping

The universal tier, and also a feature on its own: pinging a service, not a host. "Is my game server's port answering, and how fast?"

  • Measure to the SYN-ACK. The moment connect() returns (or NWConnection reaches .ready) is one round trip plus microseconds of stack time. That is the number. Close immediately with RST (linger 0) so the server never holds half a connection.
  • Never include TLS. Plain sockets only. TLS adds round trips and handshake CPU and would make the number a lie.
  • A refused port is still an answer. An RST arrives in one round trip and proves the path. Render it as a valid RTT with a "refused" tint rather than a loss.
  • Port ladder for the handshake: 443, then 80, then 53. A user-set port wins over the ladder for explicit TCP panels.
  • Implementation: Ktor raw sockets (aSocket().tcp().connect() inside withTimeout) work in commonMain across JVM, Android, and iOS, one code path. Keep a thin NWConnection variant on iOS only if interface pinning for TCP becomes a feature.
  • Cost note: a TCP probe is a real connection on the target. Default TCP panels to a 1 s interval instead of adaptive, and cap adaptive TCP at 5 probes per second. Hammering someone's accept queue at 200 Hz is abuse, not measurement.

07

Web target, without lying

A browser build (wasmJs) cannot open ICMP, UDP, or raw TCP. Anything the web version shows must be one of these, clearly labeled:

  • WebSocket RTT. Open a WS to an echo endpoint and time small frames. Honest, continuous, and the closest thing to a ping the browser allows. Needs an endpoint that speaks WS: either a tiny echo relay you host, or targets that happen to expose one. This is the primary web tier.
  • HTTPS request timing. fetch HEAD with the Performance API. Includes TLS unless the connection is reused, so it is a "service latency" number, not an RTT. Cross-origin targets hide detailed timings unless they send Timing-Allow-Origin, and every target needs CORS. Works for the user's own services, useless for 8.8.8.8.

So the web app is real but different: it measures services, not hosts, and says so in the panel. CMP already compiles this UI to wasm; the work is a wasmJs target, a browser PingEngine actual speaking WS/fetch, and honest tier labels. A relay server would make arbitrary-host pinging possible from the browser, but that turns PINGY into infrastructure; park it until wanted.

08

Benchmark screen

One target tells you about one path. The benchmark answers "how healthy is my connection", using the user's chosen duration and ending in a diagnosis, not a wall of numbers.

Protocol (phases scale with the chosen duration, 30 s to 10 min)

  • Baseline sweep. Ping the gateway, two anycast resolvers, and one far target in parallel. Collects idle latency, jitter, and loss per path.
  • DNS check. Time fresh lookups of a few uncached names against the system resolver and against 1.1.1.1 directly.
  • Loaded latency. Start a parallel download to saturate the line (the speed-test machinery from section 09), keep pinging the gateway and a resolver during it. The idle-to-loaded latency delta is bufferbloat, the thing that makes calls stutter while someone streams.
  • Recovery tail. Stop the load, watch latency settle. Slow settling implies deep queues.

Diagnosis rules (each fires a plain-language finding)

PatternFinding
Gateway clean, WAN targets badYour Wi-Fi is fine. The problem is your ISP or beyond.
Gateway already jittery or lossyLocal radio problem: interference, distance, or a busy router.
Idle latency fine, loaded latency 5x worseBufferbloat. Calls and games will suffer whenever anything downloads.
System DNS slow, direct resolver fastYour configured DNS is the bottleneck. Suggest switching.
Uniform loss on every pathReal packet loss on the link itself, not congestion on one route.
All bad on Wi-Fi, all good on cellular (if permitted to compare)The access network is the problem, not the internet.

Score is secondary to findings: a 0-100 blend of idle latency (25%), jitter (20%), loss (30%), bufferbloat delta (25%), each mapped through honest thresholds. The result screen leads with the findings in sentences, keeps the raw numbers one tap away, and reuses the panel visual language so it still feels like PINGY.

09

Download / upload speed

  • Method: parallel HTTP streams (4 to 8) with ramp-up, measured over 1-second windows, discard the first two windows, report the median of the rest. Median beats mean against bursts.
  • Servers: Cloudflare's public speed endpoints (speed.cloudflare.com/__down?bytes=N and __up) as default, LibreSpeed server URL as a user-configurable alternative for self-hosters. No SDK dependencies.
  • Upload: chunked POST of generated data, same windowing.
  • Implementation: Ktor client in commonMain with streaming bodies; OkHttp engine on Android, Darwin engine on iOS, CIO on desktop.
  • Guardrails: show projected data usage before starting on cellular (a 30 s test can eat hundreds of MB), and feed the loaded-latency phase of the benchmark instead of running its own load twice.

10

Morph catalog

Motion budget rule: one orchestrated moment per interaction, springs over tweens, everything under 350 ms, and nothing animates during scrub. The list, in order of felt impact:

  • Layout morphs. Wrap the panel area in LookaheadScope with movableContentOf panels, so switching stack, grid, and pager physically slides and resizes the same panels instead of teleporting them. This is the single most "wow" item.
  • Preset dropdown. Staggered item entrance (fade + 8 dp slide, 25 ms apart) and an animated dot that breathes once when the item lands. The menu itself already scales in; the stagger is what makes it feel alive.
  • Deck fold. Replace the current slide with animateContentSize on the chassis plus a crossfade between stats and settings, so the panel's outline morphs as one shape, matching the fused-chassis idea.
  • Readout digits. Roll digits vertically on change (AnimatedContent with slide per digit slot, throttled to the existing 150 ms sampler). Skip when the value jumps by more than 3 digits.
  • Add and remove. New panel springs in with a small overshoot (the birth ritual the bars already perform); removed panel collapses via animateItem in the lazy containers.
  • About entrance. The logo icon slides in from the left, the wordmark from the right, meeting in the middle once. Cheap, memorable, and only on that screen.

11

Backlog: the other things this app wants

  • P1 Failure-reason taxonomy: the enum (resolve failed, no route, rejected, timeout) that unlocks tiers, honest panels, and the benchmark's findings.
  • P1 Network-change listeners on both platforms, feeding the handshake and a tiny "network changed" tick mark on the graph timeline.
  • P1 Pause on background, resume on foreground. Honest battery behavior before any store release.
  • P2 Traceroute without root: Linux ping sockets deliver TTL-exceeded errors via IP_RECVERR, so hop-by-hop latency is possible on Android with the existing socket type. Darwin needs a different trick (TCP with rising TTL). A killer differentiator if it lands.
  • P2 Loss alerts: a per-panel threshold (loss over N% for M seconds) firing a local notification. Pairs with the foreground-service question.
  • P2 Session history: persist compressed per-minute aggregates (SQLDelight), a scrollable past-hour strip under the live graph.
  • P2 IPv6 end to end, per the survival map.
  • P3 Home-screen widget (Glance) showing one target's live color and value.
  • P3 Export: share a panel as PNG (the graph already draws itself; render to an ImageBitmap) or CSV of the window.
  • P3 Gateway auto-detect preset: resolve the actual default gateway instead of guessing 192.168.1.1.
  • P3 Anomaly badge: EWMA over RTT; when the live value runs 3 sigma above its own baseline, the readout pulses once. Cheap math, real signal.
  • P3 MTU probe: binary-search the largest unfragmented payload (the packet-size machinery already exists).

Suggested order of attack: taxonomy, then network listeners, then the TCP tier, then force-cellular, then the benchmark on top of all four. Each step ships alone.
